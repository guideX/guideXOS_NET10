# Next-stage blockers

Gate 4 still proves the first no-allocation managed handoff. The allocation follow-on now builds and traces the generated allocation helper, and the verified FILETIME, monotonic performance, minimal CRT on-exit initialization, x64 SLIST-head initialization, and narrow error-returning CRT initializer-table contracts advance authentic NativeAOT startup beyond QPC. The next boundary is `api-ms-win-crt-runtime-l1-1-0.dll!_initterm`; the loader's 24 functional imports in the `_initterm_e` opt-in profile remain bounded platform contracts rather than broad implementation of the following runtime services.

## Recommended next milestone

Create a one-variable-at-a-time NativeAOT CRT startup reproducer for `_initterm` and the first allocation/GC boundary. Capture imports, undefined symbols, TLS, module initializer behavior, and transition-helper changes before writing any additional UEFI platform code.
